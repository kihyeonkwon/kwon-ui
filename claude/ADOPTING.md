# 앱에 넣는 순서

앱 하나에 kwon-ui를 넣을 때 따르는 순서입니다. 한 번에 한 앱씩, 넣기 전과 후의 화면을 같은 크기로 찍어 대조합니다.

## 1. 설치

```bash
npm install kwon-ui@0.4.0 --save-exact
```

정확한 버전을 고정합니다. 올릴 때는 `CHANGELOG.md`를 읽고 한 앱씩 올립니다.

## 2. CSS 불러오기

레이아웃에서 앱의 CSS보다 먼저 불러옵니다.

```tsx
import "kwon-ui/kwon-ui.css";
import "./globals.css";
```

- 앱의 CSS가 `@layer`로 묶여 있고 kwon-ui도 같은 층에 넣어야 하면 CSS에서 `@import "kwon-ui/kwon-ui.css" layer(components);`로 부릅니다.
- 층 없이 부르면 kwon-ui의 규칙이 Tailwind 유틸리티보다 우선합니다. 그래서 조각에는 margin과 폭이 없습니다.
- 페이지 맨 바깥에 `.night`가 있어야 합니다.
- Next.js 16과 Tailwind 4에서 `@import "kwon-ui/kwon-ui.css" layer(components);`가 개발 서버(webpack)와 운영 빌드(Turbopack) 모두에서 되는 것을 확인했습니다(스킬캠퍼스, 2026-11-16). 컴포넌트와 `tone()`도 서버 컴포넌트에서 그대로 불러와 씁니다.
- 같은 층에 넣으면 특이도와 순서가 그대로 적용됩니다. kwon-ui의 규칙은 `.night .n-…`(클래스 둘)이라, 같은 요소에 붙은 앱의 한 클래스짜리 규칙(`.cp-offer { padding-top: … }`)은 집니다. 앱 쪽을 `.n-sect.cp-offer`처럼 클래스 둘로 씁니다.
- `.night`는 글자색을 흰색으로 둡니다. 앱의 기본 글자색이 다르면 바깥 요소에서 한 번 정합니다(`.cp.night { color: var(--n-soft); }`).
- 개발 서버가 떠 있는 채로 브랜치를 바꿔 CSS 파일이 사라졌다 생기면 옛 CSS가 남습니다. 불러오는 CSS 파일을 한 번 저장(touch)하면 다시 만들어집니다.
- 버튼 위의 손 모양 커서는 앱의 초기화 규칙이 줍니다(본사이트 `globals.css`의 `button { cursor: pointer }`). Tailwind 4는 버튼에 화살표 커서를 둡니다. 알약 버튼(`n-pill`)과 탭(`n-tab`)을 `<button>`으로 쓰는 앱은 `button:not(:disabled) { cursor: pointer; }`를 바탕 층에 둡니다.
- 머리 메뉴(`n-nav`)는 화면 위에 떠 있어 문서 흐름에서 자리를 차지하지 않습니다. 레이아웃의 `<header>`처럼 페이지 바깥에 둘 때는 그 요소에도 `night`를 붙입니다. 첫 구간의 위 여백은 앱이 둡니다. 스킬캠퍼스는 머리글 상자(`position: relative; z-index: 40; height: 64px`)가 휴대폰 알약 높이만큼 자리를 비우고, 넓은 화면의 메뉴 줄은 그 아래 첫 구간의 위 여백 위에 놓입니다.
- 흰 바탕 페이지가 있는 앱은 머리 메뉴만 `<div class="night 앱-감싸개">`(높이 0)로 감쌉니다. 그러면 흰 바탕 페이지에도 `.night`가 생기므로, 앱이 페이지 전체에 거는 `html:has(.night)` 규칙은 `html:has(.night:not(.앱-감싸개))`처럼 감싸개를 빼고 겁니다. 앱만의 톤(첫 화면, 흰 바탕 페이지)은 `data-tone` 같은 앱 속성과 앱 클래스로 덧붙입니다(kwonandcompany.com 의 `.kc-nav`).

## 3. 앱에 있던 같은 정의 지우기

```bash
npx kwon-ui check --report
```

`system-redefine`과 `token-redefine`으로 나오는 규칙이 앱에 남아 있는 같은 이름의 정의입니다. 지우고 화면을 대조합니다. 앱의 값이 kwon-ui와 달랐다면 그 차이가 화면에 나타납니다. 의도한 변형이었는지 보고, 필요하면 kwon-ui에 변형을 제안합니다.

`reserved-prefix`로 나오는 것은 앱에만 있는 `n-` 이름입니다. 한 번에 바꾸지 않아도 됩니다. 기준선에 두고, 그 파일을 고칠 때 앱 접두어로 바꿉니다. 한꺼번에 바꿀 때는 이름이 앞부분을 같이 쓰는 경우(`n-chart`, `n-chart-bar`)와 이미 있는 앱 이름(`kc-card` 같은 글자 클래스)과 겹치는지 먼저 보고, CSS 의 키프레임 이름과 `querySelector` 문자열도 같이 바꿉니다.

조각에 붙은 Tailwind 색·글자 클래스(`n-body text-white` 같은)는 실제로는 먹지 않습니다. kwon-ui 는 층 없이 불려 Tailwind 유틸리티(층 안)를 이깁니다. 그런 클래스는 지워도 화면이 바뀌지 않습니다. 정말 다른 색이 필요하면 `.hi` 같은 변형이나 앱 클래스를 씁니다.

쓰지 않는 앱 클래스를 지울 때는 주석만 뺀 코드 전체에서 이름이 낱말로 한 번이라도 나오는지 봅니다. 템플릿 문자열의 `${…}` 안 문자열을 빼고 찾으면 조건으로 붙는 클래스(`` `n-chart${compact ? " compact" : ""}` ``)를 놓칩니다.

## 4. 설정과 기준선

앱 루트에 `kwon-ui.config.json`을 둡니다.

```json
{
  "roots": ["src"],
  "exclude": [],
  "tokenFiles": ["src/app/tokens.css"]
}
```

- `roots`: 검사할 폴더. 화면과 상관없는 폴더는 `exclude`에 넣습니다.
- `tokenFiles`: 앱 고유의 색(강조색 등)을 변수로 정의하는 파일. 색 값을 직접 쓸 수 있는 곳은 여기뿐입니다.

```bash
npx kwon-ui baseline
```

지금의 위반 수가 `kwon-ui.baseline.json`에 적힙니다. 커밋합니다. 이 수는 줄어들기만 해야 합니다. 위반을 고쳤으면 다시 `baseline`을 돌려 수를 낮춥니다.

## 5. 빌드에 걸기

```json
{
  "scripts": {
    "check:design": "kwon-ui check",
    "prebuild": "npm run check:design"
  }
}
```

위반이 기준선보다 늘면 빌드가 실패합니다. 어떤 도구로 작업해도 똑같이 걸립니다.

## 6. Claude Code 훅

파일을 저장할 때마다 그 파일만 검사해서, 위반이 늘었으면 내용을 모델에게 바로 돌려줍니다. 작업 공간의 Claude Code 설정(`.claude/settings.json`)에 한 번 겁니다. 아래 모양으로 걸어 실제로 되돌아오는 것을 확인했습니다(2026-11-16).

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "command -v node >/dev/null 2>&1 || exit 0; node /경로/kwon-ui/claude/hook.mjs", "timeout": 20 }]
      }
    ]
  }
}
```

훅은 `kwon-ui.config.json`이 있는 앱 안의 `.css`, `.tsx` 파일만 봅니다. 그 밖의 파일과 오류는 조용히 지나갑니다.

## 넣기 전과 후를 대조하는 법

넣기 전의 화면에서 모든 요소의 자리(x, y, 폭, 높이)와 계산된 스타일을 기록해 두고, 넣은 뒤 같은 방법으로 기록해 요소 순서대로 맞춰 봅니다. 화면 폭은 390, 768, 1024, 1440 네 가지로 잽니다. 같은 화면을 두 번 재서 차이가 0인지 먼저 확인합니다(움직이는 조각은 빼고 잽니다). 남는 차이가 kwon-ui의 값을 받아들인 것뿐이면 끝입니다. 스킬캠퍼스는 이 방법으로 네 페이지를 대조했고, 페이지 길이 차이는 16,000px 가운데 4px 안팎이었습니다.

## 넣을 때 알아 둘 차이

값의 기준은 kwonandcompany.com입니다. 0.1.0은 계산된 스타일이 홈페이지와 같고, 0.2.0에서 아래 두 가지가 달라졌습니다. 다른 두 제품은 손으로 옮기면서 생긴 작은 차이가 있어, 넣으면 그만큼 바뀝니다.

- kwonandcompany.com(2026-11-16 기준선 0): 1단계에서 겹치는 정의를 지우고, 2단계에서 머리 메뉴를 `n-nav`로 옮기고(첫 화면과 흰 바탕 페이지의 톤은 앱의 `.kc-nav`), 3단계에서 앱에만 있는 `n-` 이름 102개를 `kc-`로 바꾸고 남은 직접 값을 앱 토큰으로 옮겼습니다. 인쇄할 때 제목 색을 바꾸는 규칙은 조각을 다시 정의하는 것이라, 앱 본문 영역(`main.kc-main`) 안으로 범위를 좁혀 덮어쓰기(경고)로 둡니다. 화면이 바뀐 곳은 바닥글 둘뿐입니다. 칸 이름을 모든 페이지에서 첫 화면 쪽 값(작은 글과 같은 14px, 400, `--n-mid` 과 같은 50%)으로 맞췄고, 문단 기본색에 가려 거의 안 보이던 저작권 줄을 같은 줄의 링크와 같은 색으로 바꿨습니다. 0.2.0 에서 달라진 두 가지는 아래와 같습니다.
- kwonandcompany.com: 줄 목록의 라벨이 본문 첫 줄의 밑선에 맞춰져 넓은 화면에서 4px 내려갑니다(`items-baseline`을 이미 준 줄은 그대로입니다). 교육 문의의 사진 판(`n-closing`)을 `n-photo`로 바꾸면 1024px 미만에서 최소 높이가 560px → 480px, 제목과 문단 사이가 20px → 16px, 제목의 회색 글자가 50% → 62%가 됩니다. 문단과 버튼 줄 사이는 버튼 줄을 `n-actions`로 두면 40px 그대로입니다. 사진 판 안의 `mt-5`, `mt-10`은 뺍니다.
- Projects 랜딩: 제목 줄 간격 1.25 → 1.2, 본문 1.55 → 1.5, 알약 버튼 글자 사이 0.01em과 간격 10px, 글자 링크 간격 8px, 구간 머리의 세로 정렬(위 → 가운데). 구간 사이의 선(`n-sect n-rule`)을 `n-sect ruled`로 바꾸면 선이 바깥 여백만큼 짧아져 내용 폭과 같아집니다.
- 스킬캠퍼스(2026-11-16 공개 네 페이지에 넣음): 변수 이름을 바꿨습니다(`--hi`, `--mid`, `--line` 등 → `--n-hi`, `--n-mid`, `--n-line`). 바뀐 값은 작은 글 줄 간격 1.5 → 1.45, 글자 링크의 줄 높이 1.4 → 1.6, 줄 목록 라벨의 글자 사이 0, 검은 판의 z-index 1입니다. 0.2.0으로 올리면서 앱이 덧붙여 쓰던 규칙(구간 선, 짧은 구간, 줄 목록의 첫 줄 맞춤, 진한 낱말, 사진 판)을 지웠습니다. 0.3.0에서는 약관 세 페이지를 긴 글(`n-prose`)과 표(`n-table`)로, 로그인과 가입을 입력 칸(`n-label`, `n-field`)으로 옮겼습니다. 바뀐 값은 입력 칸 높이 48 → 52px, 모서리 4 → 12px, 칸 이름 13px 500 → 14px 400 회색, 약관 본문 15.5 → 18px, 표 글자 13.5 → 14px입니다. 0.4.0에서는 머리글을 머리 메뉴(`n-nav`)로, 계정 탭을 탭(`n-tabs`)으로, 버튼(`.btn`)을 알약 버튼(`n-pill`)으로 옮겼습니다. 바뀐 값은 넓은 화면 메뉴 줄의 자리(줄 가운데 32px → 본사이트와 같은 위 여백 + 21px, 1440에서 65px), 넓은 화면 알약의 위 여백 12 → 16px, 알약과 메뉴판의 유리 rgba(24,24,24,.62)와 .92 → rgba(30,30,36,.55), 메뉴판 폭 360 → 330px, 메뉴판 버튼 높이 48px 알약 → 40px 모서리 8px, 메뉴판 링크의 화살표 없앰, 버튼의 투명 테두리 1px 없앰(폭 2px 줄어듦), 작은 버튼 글자 13 → 14px, 계정 탭 세 칸 나눔 → 알약 묶음입니다.
